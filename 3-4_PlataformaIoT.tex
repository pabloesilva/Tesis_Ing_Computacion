\chapter{Plataforma IoT}

La implementación final de la plataforma de supervisión se llevó a cabo materializando la arquitectura de microservicios descrita anteriormente. El sistema se despliega sobre un entorno contenerizado con Docker, lo que permitió aislar las dependencias de cada servicio y garantizar la portabilidad del software entre el entorno de desarrollo y el servidor de producción (VPS).

A continuación se detallan los aspectos técnicos del desarrollo del backend y el diseño de la interfaz de usuario.

\section{Desarrollo del Backend y Procesamiento}

El núcleo lógico de la plataforma reside en dos componentes de software desarrollados en lenguaje Python:

\begin{enumerate}
    \item \textbf{Gestor de Telemetría (MQTT Worker):} Se implementó un script que opera como demonio (servicio en segundo plano). Este componente utiliza la librería \texttt{paho-mqtt} para suscribirse al broker y recibir en tiempo real los paquetes de datos JSON enviados por el AC. Su función es decodificar los payloads, validar que los valores eléctricos (tensión, corriente, potencia) se encuentren en rangos físicos coherentes y persistir la información en la base de datos MariaDB.
    
    \item \textbf{Servidor de Aplicación (Flask):} Para la lógica web se utilizó el micro-framework Flask. Este se encarga de exponer los endpoints o rutas de la aplicación, gestionar las consultas SQL a la base de datos histórica y servir las plantillas HTML al navegador del cliente.
\end{enumerate}

\section{Diseño de Interfaz y Experiencia de Usuario}

La interfaz visual (Frontend) fue construida utilizando el motor de plantillas Jinja2 integrado en Flask, combinado con el framework CSS Bootstrap para garantizar la adaptabilidad (diseño responsivo) en diferentes tamaños de pantalla.

Para dotar al sistema de una estética profesional y limpia, se seleccionó el tema Cerulean de la suite Bootswatch. Este tema se caracteriza por el uso de tonalidades azules y una tipografía clara que facilita la lectura de datos técnicos. Adicionalmente, se implementó mediante JavaScript una funcionalidad de cambio de modo (Claro/Oscuro), permitiendo al operador ajustar el contraste de la interfaz según las condiciones de iluminación del entorno, tal como se aprecia en la Figura~\ref{fig:iot}.

\section{Migración de la plataforma a Grafana}

Debido a la necesidad de contar con un sistema de visualización más robusto y flexible, se decidió migrar la plataforma de monitoreo hacia Grafana. Esta herramienta permite crear dashboards interactivos y altamente personalizables, facilitando la integración de múltiples fuentes de datos y ofreciendo una mejor experiencia de usuario. Por otro lado, Grafana proporciona soporte nativo para bases de datos orientadas a series temporales, lo que mejora significativamente la eficiencia en la gestión de grandes volúmenes de datos históricos.

\subsection{Migración a bases de datos orientadas a series temporales}

En la implementación actual, el almacenamiento de la información se realiza mediante una base de datos relacional, lo cual resulta adecuado para el manejo estructurado de datos y relaciones entre entidades, pero presenta limitaciones cuando se trata de gestionar grandes volúmenes de datos indexados en función del tiempo. Como alternativa, se tiene el almacenamiento de datos orientado a series temporales (TSDB).

En sistemas de monitoreo como el propuesto, donde se generan continuamente mediciones de variables como corriente, tensión o potencia, el tiempo se convierte en el atributo principal de los datos. En este contexto, las bases de datos de series temporales ofrecen ventajas significativas, ya que están diseñadas específicamente para la inserción eficiente de datos secuenciales, consultas basadas en ventanas temporales y almacenamiento optimizado mediante técnicas de compresión y retención de datos.

Por este motivo, se decidió realizar la migración hacia una solución basada en TSDB para mejorar el rendimiento en la escritura y consulta de datos, facilitando la implementación de funcionalidades avanzadas, tales como agregaciones automáticas, \textit{downsampling}, definición de políticas de retención y análisis de tendencias a lo largo del tiempo, lo cual resulta particularmente relevante para la evaluación de hábitos de consumo y la optimización del sistema.

Se optó por utilizar InfluxDB, una de las bases de datos de series temporales más populares y ampliamente adoptadas, debido a su facilidad de integración con Grafana y su capacidad para manejar grandes volúmenes de datos con alta eficiencia. La implementación se llevó a cabo mediante la creación de un contenedor Docker específico para este servicio, configurando los parámetros de almacenamiento y retención de datos manteniendo la compatibilidad con el esquema previamente definido en la base de datos relacional. Además, se adaptó el worker MQTT para que, en lugar de persistir los datos en MariaDB, los enviara a InfluxDB utilizando la API de escritura de la base de datos.

\subsection{Integración con Grafana}

Con el fin de mantener la coherencia en la visualización de los datos, se creó un dashboard personalizado que replica y mejora las funcionalidades del panel de control original, permitiendo a los usuarios explorar los datos históricos y en tiempo real mediante gráficos interactivos, tablas y alertas configurables.

Como se puede observar en la Figura~\ref{fig:grafana-dashboard}, la interfaz de Grafana ofrece la misma experiencia visual que el panel de control original, pero con opciones de filtrado, selección de rangos temporales y visualización de métricas agregadas, lo que facilita la toma de decisiones informadas sobre el consumo energético y la gestión de los nodos conectados.
