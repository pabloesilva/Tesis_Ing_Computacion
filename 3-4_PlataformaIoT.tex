\section{Desarrollo del Backend y Procesamiento}

El núcleo lógico de la plataforma reside en dos componentes de \ing{software} desarrollados en lenguaje Python:

\begin{enumerate}
    \item \textbf{Gestor de Telemetría (MQTT \ing{Worker}):} Para esto fue implementado un \ing{script} que opera como demonio (servicio en segundo plano). Este componente utiliza la librería \texttt{paho-mqtt} para suscribirse al \ing{broker} y recibir en tiempo real los paquetes de datos JSON enviados por el AC. Su función es decodificar los \ing{payloads}, validar que los valores eléctricos (tensión, corriente, potencia) se encuentren en rangos físicos coherentes y persistir la información en la base de datos MariaDB.
    
    \item \textbf{Servidor de Aplicación (Flask):} Para la lógica web se utilizó el \ing{micro-framework} Flask. Este es el encargado de exponer los \ing{endpoints} o rutas de la aplicación, gestionar las consultas SQL a la base de datos histórica y servir las plantillas HTML al navegador del cliente.
\end{enumerate}

\section{Diseño de Interfaz y Experiencia de Usuario}

La interfaz visual (\ing{Frontend}) fue construida utilizando el motor de plantillas Jinja2 integrado en Flask, combinado con el \ing{framework} CSS Bootstrap para garantizar la adaptabilidad (diseño responsivo) en diferentes tamaños de pantalla.

Para dotar al sistema de una estética profesional y limpia, fue seleccionado el tema Cerulean de la suite Bootswatch. Este tema tiene tonalidades azules y una tipografía clara que facilita la lectura de datos técnicos. Adicionalmente, se implementó mediante JavaScript una funcionalidad de cambio de modo (Claro/Oscuro), permitiendo al operador ajustar el contraste de la interfaz según las condiciones de iluminación del entorno, tal como se aprecia en la Figura~\ref{fig:iot}.

\section{Migración de la plataforma a Grafana}

Debido a la necesidad de contar con un sistema de visualización más robusto y flexible, la plataforma de monitoreo fue migrada a Grafana. Esta herramienta permite crear \ing{dashboards} interactivos y altamente personalizables, facilitando la integración de múltiples fuentes de datos y ofreciendo una mejor experiencia de usuario. Por otro lado, Grafana proporciona soporte nativo para bases de datos orientadas a series temporales, lo que mejora significativamente la eficiencia en la gestión de grandes volúmenes de datos históricos.

\subsection{Migración a bases de datos orientadas a series temporales}

En la implementación original, el almacenamiento era realizado en una base de datos relacional (MariaDB), adecuada para el manejo estructurado de datos pero limitada para gestionar grandes volúmenes de mediciones indexadas en el tiempo. Por los motivos expuestos en la Sección~\ref{sec:tsdb}, se decidió migrar hacia una base de datos de series temporales, lo que mejora el rendimiento de escritura y consulta, también habilita funcionalidades como agregaciones automáticas, \ing{downsampling} y políticas de retención, particularmente relevantes para la evaluación de hábitos de consumo en las diferentes cargas del sistema.

Se optó por InfluxDB debido a su soporte nativo en Grafana y a su capacidad para manejar grandes volúmenes de datos con alta eficiencia. La implementación fue llevada a cabo mediante un contenedor Docker específico, configurando los parámetros de
almacenamiento y retención y manteniendo la compatibilidad con el esquema previamente definido en la base de datos relacional. Además, se adaptó el \ing{worker} MQTT para que, en lugar de persistir los datos en MariaDB, los enviara a InfluxDB utilizando su API de escritura.

\subsection{Integración con Grafana}

Con el fin de mantener la coherencia en la visualización de los datos, fue creado un \ing{dashboard} personalizado que replica y mejora las funcionalidades del panel de control original, permitiendo a los usuarios explorar los datos históricos y en tiempo real mediante gráficos interactivos, tablas y alertas configurables.

Como puede observarse en la Figura~\ref{fig:grafana-dashboard}, la interfaz de Grafana ofrece la misma experiencia visual que el panel de control original, pero con opciones de filtrado, selección de rangos temporales y visualización de métricas agregadas. Lo que facilita la toma de decisiones informadas sobre el consumo energético y la gestión de los nodos conectados.
